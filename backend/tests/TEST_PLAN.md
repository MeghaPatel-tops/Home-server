# Backend Test Suite Overview

This document outlines a **full‑backend test strategy** for the HomeServe project.  All tests are written with **Jest** and use **Supertest** for end‑to‑end HTTP calls.  Business logic is mocked (services, models) to keep the suite fast and deterministic.

## Directory layout (under `backend/tests`)
```
backend/tests/
├─ auth.routes.test.js          # Auth endpoints (login, register, logout)
├─ user.routes.test.js          # User profile & address endpoints
├─ booking.routes.test.js       # Booking flow (create, cancel, provider queue, technician actions)
├─ provider.routes.test.js      # Provider‑specific routes (e.g., fetching queue)
├─ zones.routes.test.js         # Serviceability & zone look‑ups
├─ health.test.js               # Health & public routes (already existing)
└─ auth.service.test.js        # Unit tests for AuthService (already existing)
```

Each file follows the same pattern:
1. **Import `app`** from `src/app`.
2. **Mock the corresponding service** (e.g. `catalog.service`, `booking.service`).
3. Use **Supertest** to fire HTTP requests against the Express app.
4. Verify **status codes**, **response shape**, and that the mock service was called with expected arguments.

> The tests intentionally avoid hitting a real DB.  If you need integration tests with a live DB, spin up a test database and add a separate `e2e/` folder.
